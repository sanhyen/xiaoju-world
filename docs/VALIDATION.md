## 检查中修复的问题

- 替换媒体清单时遗漏场馆关联字段，导致活动点未完整创建；补回结构字段并重新烘焙后，501 个既有 ID 检查通过。
- 路径处理误将资源 URI 识别为个人路径；恢复项目资源 URI 后，导入与场景启动通过。
- 文字检查脚本使用了不兼容的哈希方法；改用 `HashingContext`，重新读取场景并核对实际缓冲后通过。
- 普通输入脚本误用 P 退出拍照模式；改为游戏实际使用的 Esc。窗口被其他置顶程序遮挡时检查保护会停止输入；仅将本次临时游戏窗口置前后完成检查。

原失败日志与通过日志分别保存在本地 `reports`，不会把失败记录计作通过证据，也不随普通源码提交分发。

这些结果只覆盖公开版修改及受影响功能，不代表全地图逐点艺术验收、所有电脑性能保证或全部历史检查重新执行。

## 复现

按[构建说明](BUILD.md)执行 `import`、`check`、`smoke`、`restore`、`audit`。导出后可在 Windows 上执行下列检查，期间保持测试游戏窗口在前台：

```powershell
python tools/verify_windows_input.py --destination "解压后的 XiaojuWorld 文件夹" --label my_first_check
```

每次使用新的 `--label`，保留旧检查记录。日志和隔离用户目录分别位于本项目的 `reports` 和 `.runtime`。
